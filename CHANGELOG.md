# Changelog

Written as changes land, not at release (DESIGN.md §2.9).

## Unreleased

### M1: ghostty

- `ghostty-vt-ffi-test` is the full layout test (DESIGN.md §3.4): it parses the linked library's
  `ghostty_type_json()` and checks every bound struct's size, alignment, field names, offsets and
  sizes, and every named enum value, against the binding's `hsc2hs` values. The binding exports those
  values as descriptors (`Ghostty.FFI.Layout`), and binds `ghostty_type_json`. Each struct's `Storable`
  instance is checked against its descriptor (size, alignment, and a poke/peek round trip over
  zeroed and all-ones memory). Each enum's `Unknown` view is built from its descriptor and checked,
  through a total match, to exclude exactly the named values. `scripts/check-layout-rows.py`, in CI,
  fails if a bound type has no descriptor or no row.
- `GhosttyBuildInfo` has the `COMPLETE` set and `GhosttyBuildInfoUnknown` view §3.3 requires, which
  M0 left out.
- `ghostty-vt-ffi` binds `terminal.h` (M1.2): `Ghostty.FFI.Terminal` (lifecycle, every
  `GhosttyTerminalOption` and `GhosttyTerminalData` key with its type documented, VT writes,
  `vt_write_until` and its boundary enums, continuations, the viewport, compression, grid refs) and
  `Ghostty.FFI.Terminal.Callbacks` (every callback type with a `wrapper`, and the structs they
  receive). Also `Ghostty.FFI.GridRef` (untracked and tracked refs), `Point`, `Style`, `Device`,
  `Modes`, `Allocator`, and the parts of `color.h`, `osc.h`, `size_report.h`, `io.h` and `screen.h`
  these need. 59 descriptors, each with a layout-test row, and a behavioural test of the shims,
  callbacks and `vt_write_until`.
- DESIGN.md §3.3, §4.5 and §14.2: five functions take a struct by value, so they call
  `static inline` pointer shims (`include/gvtffi_shims.h`). The `ENQUIRY` and `XTVERSION` callbacks
  return one, so no Haskell function can be them. `terminal_reset`, `_resize`, `_set` and
  `_continuation_write` are `safe` as well as the writes, because each can run a callback, and
  `_compress` is `safe` because a full pass can stall. Tagged unions are sums, and the binding never
  supplies an allocator.
- `ghostty-vt-ffi`'s mechanical code is generated from the pinned headers by
  `scripts/gen-ghostty-ffi.py`, from templates in `ghostty-vt-ffi/gen/`, and CI checks it is current
  (`--check`). Callback types are derived from their C typedefs, and their docs are the header's.
- `scripts/check-ghostty-coverage.py`, in CI, fails on any function or type in the pinned headers
  that is neither bound nor listed in `ghostty-vt-ffi/coverage.txt` with the PLAN.md step that binds
  it, and on an entry that no longer defers anything. 132 symbols are bound and 295 deferred.
- The layout test requires every enum to name every value the library has, so a value a pin bump
  adds fails the test. `build_info.h` is now bound whole for it (`GhosttyBuildInfo`'s other eight
  keys, and `GhosttyOptimizeMode`), and DESIGN.md §2.8, §3.1, §3.3 and §3.4 say so.
- `ghostty-vt-ffi` binds render state and formatting (M1.3's first half, of the two the plan allows):
  `render.h` whole as `Ghostty.FFI.Render` (render state, update phases, every data key and
  option, row, cell and image-placement iterators, dirty iteration, row ids, the sized cursor and
  colour structs); `screen.h` whole as `Ghostty.FFI.Screen` (cell and row keys, the bulk cell view),
  now generated rather than hand-written; `selection.h` whole as `Ghostty.FFI.Selection`
  (selections, word/line/output/all derivation, adjust, order, contains, equal, one-shot formatting,
  and the gesture state machine); `formatter.h` whole as `Ghostty.FFI.Formatter`; and `types.h`'s
  `GhosttyFormatterFormat`, `GhosttyBuffer`, `GhosttyCodepoints` and `GhosttySurfacePosition`.
  105 descriptors, each with a layout-test row, and behavioural tests of each new shim, the dirty
  iteration, and the agreement of every reading path (keyed, raw, bulk, sized struct) and every
  output path (writer, buffer, allocation). 241 symbols bound, 186 deferred.
- DESIGN.md §3.3 and §14.2: at the pin, 18 functions take a struct by value and one returns one, so
  `include/gvtffi_shims.h` is now generated by `scripts/gen-ghostty-ffi.py` (`{{shim F}}`), M1.2's
  five shims with it; eleven are bound. `io.h`'s `GhosttyMimeReaderFn` receives structs by value,
  so like `ENQUIRY` and `XTVERSION` it can only be written in C. The formatter's and selection's
  format calls are `safe` although they run no callback, because they walk the scrollback.
- DESIGN.md §3.3, §5A.2 and §14.2: `capi` checks less than §3.3 said. A probe (GHC 9.12.4, GCC 16)
  showed that an integer of the wrong width or signedness converts silently and truncates, and that a
  `Ptr` to a Haskell type, so every struct pointer and every handle, reaches C as `void *` and is
  accepted for any pointer. `scripts/check-ghostty-signatures.py`, in CI, now compares each of the 94
  `capi` imports, the 22 callback types and the 48 struct records with the headers' C types by name.
  Mutating a width, a handle, a result, a pointee, a field, an array, a union arm, a synonym or a
  callback parameter each fails it. `tree-sitter-ffi` gets the same check at M4.1.
- `scripts/check-ghostty-safety.py`, in CI, ties each `safe`/`unsafe` decision to a fingerprint of
  the function's header doc and prototype (`ghostty-vt-ffi/safety.txt`), so a pin bump that changes
  what a bound function documents fails until it is re-read and recorded with `--update`. The 94
  decisions were recorded as they stand; no header doc of an `unsafe` call mentions a callback.
- `ghostty-vt-ffi` binds encoders, parsers and unicode (M1.3's second half), completing M1.3:
  `key/event.h` and `key/encoder.h` (`Ghostty.FFI.Key.Event`, `.Key.Encoder`: key events,
  `GhosttyMods`, every `GhosttyKey`, the encoder and its options, `GhosttyKittyKeyFlags`);
  `mouse.h`, `mouse/event.h` and `mouse/encoder.h` (`Ghostty.FFI.Mouse`, `.Mouse.Event`,
  `.Mouse.Encoder`, with `GhosttyMouseShape`); `focus.h`, `paste.h` (including
  `ghostty_terminal_paste`), `color_scheme.h`, `sgr.h` (the SGR parser, `GhosttySgrAttribute` as a
  sum, `GhosttySgrUnderline`) and `unicode.h` whole; and the rest of `color.h` (parsing, palettes,
  the X11 table, luminance), `osc.h` (the OSC parser), `modes.h` (DECRPM), `size_report.h` (the
  encoder) and `io.h` (readers and the MIME reader). `GhosttyKittyGraphics` is bound as a handle
  (`Ghostty.FFI.KittyGraphics`); the rest of `kitty_graphics.h` stays with M6.15. 357 symbols
  bound, 70 deferred, all to M6 or never. 133 descriptors, each with a layout-test row, and
  behavioural tests of every encoder against the sequence it is specified to produce, the six new
  shims, both parsers, the width tables, the colour calls, and a paste into a terminal through a C
  MIME reader (`test/cbits/gvtffi_test.c`) and a Haskell `WRITE_PTY` callback (403 tests).
- DESIGN.md §3.3: seventeen of the nineteen by-value functions now have shims. `ghostty_terminal_paste`
  is `safe` (it runs the MIME reader and `WRITE_PTY`); every other new call is `unsafe`, including
  `paste_is_safe` and `paste_encode`, one pass over a caller's buffer. `gen-ghostty-ffi.py` gains
  `{{defines}}`, for constants a header spells as `#define`s over a scalar typedef (`GhosttyMods`,
  `GhosttyKittyKeyFlags`, the named palette colours), `float`, and callback types that receive a
  struct by value (no `wrapper`). A value pattern that would be its enum's `Unknown` view
  (`GHOSTTY_MOUSE_BUTTON_UNKNOWN`) takes a `Value` suffix. 169 imports, 24 callback types and 56
  struct records pass the signature check, and 169 `safe`/`unsafe` decisions are recorded.

- `ghostty-effectful` has the `Ghostty` effect and scoped terminals (M1.4). `Ghostty` is statically
  dispatched; its operations are plain functions in their modules. `runGhostty` refuses to run
  against any library but the pinned build, returning `Left VersionMismatch`, and every operation
  throws `WrongThread` unless it runs on the thread that ran `runGhostty`.
  `Ghostty.Effectful.Terminal` has `withTerminal` (a rank-2 region, freed by `bracket` on every
  path), `resize`, `reset` and `openTerminals`; a grid extent is never zero (`Extent`).
  `Ghostty.Effectful.Error` has the thrown `GhosttyError` (`OutOfMemory`, `WrongThread`,
  `Invariant` with a closed `ResultCode`). Tests: a mismatch runs nothing, a terminal is freed on
  return, when nested and when its scope throws, and use from a forked thread throws.
- `gen-ghostty-ffi.py`'s `{{pin}}` writes `GHOSTTY_COMMIT` into `Ghostty.FFI.BuildInfo` as
  `ghosttyPinnedCommit`, which the version check compares with the linked library's build metadata.
- DESIGN.md §2.7, §3.4, §4.2, §4.6 and §4.7: `Ghostty` stays static, with one interpreter, since
  libghostty-vt is its own test double; a dynamic `makeEffect` version was tried and dropped, as it
  would put every operation's constructor in one GADT. `GhosttyError` gains `WrongThread`
  and drops `BufferTooSmall` (it never escapes), and `Rejected` and `LimitExceeded` arrive with
  the calls that return them.
- `ghostty-effectful` has typed keys (M1.5). `TerminalData a` and `TerminalOption a`
  (`Ghostty.Effectful.Terminal.Keys`) have a constructor per header row, read with `getT` and
  written with `setT`. A read the header says may have no value is a `Maybe`, and an option takes a
  `Maybe` where the header's null means unset or default. The values are plain types:
  `Ghostty.Effectful.Color` (`Rgb`, a total `Palette`), `.Style`, `.Point` (`Point c`, the coordinate
  system in the type), and `.Mode`, whose `ModeKey r` is indexed by whether the library accepts a
  reset default for the mode, so `SetModeDefault` cannot take one it refuses. `TerminfoName` and
  `ChecksumExtension` make the other two refusable writes unrepresentable. The callback options,
  `SELECTION` and `KITTY_GRAPHICS` are left to M1.6, M6.5 and M6.15.
  A constructor is named for its header row, and a test checks that its marshalling sends that
  row's number.
- Tracked grid references (`TrackedRef s`: `track`, `refPoint`, `moveRef`, `refAlive`, `untrack`,
  `openTrackedRefs`) are owned by their terminal's region and freed with it. `untrack` is
  idempotent, and an untracked reference is never passed to the library again.
- Tests: every data key on a fresh terminal against its expected value; every option written and
  read back where a key reads it; the constructors plus the deferred rows equal the header's enums;
  the mode list equals the modes the library answers for, out of all 2¹⁶ mode numbers, and each
  mode's index matches what the library accepts; references follow their cell into the scrollback,
  refuse points outside the grid, and are freed by `untrack` or with their terminal.
- DESIGN.md §3.3, §4.4, §4.7 and §4.8: the high level closes C enums without an unknown case, and a
  value outside the set throws the new `GhosttyError` constructor `UnknownEnum`. The version check
  and the layout test together rule that value out. §4.4 gains the option rules, the mode index,
  the deferred rows and tracked references.

- `ghostty-effectful` has events and `feed` (M1.6, DESIGN.md §4.5). The binding installs every
  terminal callback but `CLIPBOARD_READ`; each only appends to the terminal's buffer, and is guarded
  so that no exception reaches C (one is thrown after the write instead). `feed` writes with
  `vt_write_until` stopping after each OSC, and between stops reads the cursor for each OSC 133 mark
  and the new title or working directory. `TerminalEvent` and its values are
  `Ghostty.Effectful.Event`. `resize` and `reset` now return the events they cause (the end of a
  render hold, mode 2048's size report).
- `TerminalConfig` answers the program's queries: colour scheme, device attributes, ENQ, XTVERSION
  and size, and whether clipboard writes are accepted. Each is a `TerminalOption` named for its
  callback's row (`SetColorScheme`, `SetDeviceAttributes`, `SetEnquiry`, `SetXtversion`, `SetSize`,
  `SetClipboardWrite`). ENQ and XTVERSION are answered in C (`cbits/gveff_answers.c`), because their
  callbacks return a struct by value. The grid types moved to `Ghostty.Effectful.Internal.Size`.
- Tests: the events of a mixed OSC 133 / bell / title stream, in order, and the same with the
  stream split at every byte; a mark ended by `ESC \` reads the cursor right after it; query
  replies arrive as `WritePty` and follow each answer option; clipboard, notification, progress,
  program status, render hold, reset, resize-request and unsupported-sequence events.
- Fixed in review, each with a numbered regression case: a failure resolving one OSC stop's events
  stopped `feed` there, so the rest of the input never reached the terminal (regression 1; every
  byte is now written, and the failure thrown after); replies were joined only within one stop, so
  an OSC between two replies split them into two writes (regression 2); `setT` causing no event is
  now held by a test rather than assumed (regression 3); the clipboard-write callback read its
  request without checking the struct's `size` (regression 4; a short one is `ShortStruct`, a new
  `GhosttyError`, and the write is denied). A refused `resize` now restores the size its queries
  report. The calls that resolve events moved to `Ghostty.Effectful.Internal.Feed`, which reads the
  terminal's keys directly instead of taking a reader from every caller.

- `ghostty-effectful` has render states and frames (M1.7, DESIGN.md §4.3), in
  `Ghostty.Effectful.Render`. `withRenderState` scopes a render state to a rank-2 region inside its
  terminal's; `withFrame` updates it and scopes a frame (tag `f`), whose `dirtyRows`/`allRows` and
  their `cells` are borrowed until the next update. Cells are copied into `Cell`
  (`Ghostty.Effectful.Cell`: text, width, style, resolved colours, hyperlink, protection, OSC 133
  content). A frame that returns consumes its changes (`ghostty_render_state_clean`); one that throws
  leaves them for the next. Frame and row data are typed keys (`FrameData`, `RowData` in
  `Ghostty.Effectful.Render.Keys`), each held against the header with its deferred rows, as M1.5's
  are; the cell keys a copy reads are held the same way.
- A synchronized-output hold (mode 2026) shows the frame from when it began: the `RENDER_HOLD`
  callback is now C (`cbits/gveff_terminal.c`, renamed from `gveff_answers.c` with the terminal's
  `USERDATA` now a struct), which updates every render state attached to the terminal, as the header
  asks, before calling the Haskell callback that appends the event. A hold the caller ends by
  turning the mode off with `setT` ends at once. A hold that begins while a frame of a render
  state is open does not capture into it, since that would invalidate the rows being read.
- A hyperlink's URI is read from the terminal, so a cell has it only while the terminal is still the
  frame's moment: not in a held frame, nor after the terminal was written to, which a new count of
  changes on each terminal tells.
- Tests: only the rows changed since the last frame are dirty; copied cells survive the next update;
  rows read in any order; styles, palette colours, wide and combining characters, links,
  background-only cells, semantic content; every hold case above; every frame and row key on a fresh
  frame and against the header; row identity through a scroll; the cursor outside the viewport.
- Fixed in review: a hold ended by `setT` turning mode 2026 off was dropped only at the next frame,
  so turning it on again first brought the old hold's frame back (regression 5; `setT` now drops
  the captures itself, and `withFrame` no longer reads the mode). `withFrame` opens and arms its
  frame under `mask`, so an asynchronous exception cannot leave it open for good; a render state
  with no rows has no rows, not 65536; a row move that fails no longer leaves a stale count for the
  next read. `setOption` counts every write itself, and a render state keeps its `Terminal`.
- `Ghostty.Effectful.Format` (M1.8): `format` renders a terminal's active screen, scrollback
  included, as plain text, VT or HTML, and `formatRange` a range of it (`Span`, `Block` or
  `WholeRows`, in any coordinate system; `Nothing` when an end is outside it). Options: unwrap,
  trim, and the terminal and screen extras VT output can carry. A formatter is made and freed inside
  each call, so a range's untracked grid references cannot go stale (DESIGN.md §4.2).
- Formatter goldens (`ghostty-effectful/test/golden/format/`) over canned streams: colours (16, 256,
  direct, attributes), wide and combining characters and a ZWJ sequence, soft wraps (and `unwrap`),
  OSC 8 links ended by ST and BEL, and scrollback; each in plain, VT and HTML, plus a row range, a
  block, a span, and VT without trimming.
- Fixed: a scrollback point past the end of the scrollback resolved to an active-area row, since
  the library bounds a history row only by the whole screen; `track`, `moveRef` and `formatRange`
  now refuse it (regression 6; DESIGN.md §4.4).
- Fixed: `refPoint @'History` of a reference to an active-area cell gave a scrollback row past the
  scrollback (the cell's screen row), the converse of regression 6; it is now `Nothing`
  (regression 7; DESIGN.md §4.4).
- `Ghostty.Effectful.Encode` (M1.9): key and mouse encoders as scoped handles (`withKeyEncoder`,
  `withMouseEncoder`), configured by `KeyOptions`/`MouseOptions` or from a terminal's modes
  (`keyOptionsFrom`, `mouseOptionsFrom`); focus, size, mode (DECRPM) and colour-scheme reports;
  `paste` into a terminal, which returns `Either Rejected [TerminalEvent]` (DESIGN.md §4.7), through
  a C MIME reader (`cbits/gveff_paste.c`); and the terminal-free `isPasteSafe` and `encodePaste`.
  The events encoders take are plain values in `Ghostty.Effectful.Input`: `Key` (every
  `GhosttyKey`, held against the header), `Mods` (a side only with its modifier), `KeyEvent`,
  `MouseEvent`. A cell of zero pixels, which the library ignores, cannot be given (`Extent`).
- `Ghostty.Effectful.Parse` (M1.9): `parseSgr` (parameters and their separators to
  `SgrAttribute`s) and `parseOsc` (a sequence's body to its `OscCommand`, with unimplemented
  numbers kept to a limit), each on a parser made and freed in the call. `Ghostty.Effectful.Unicode`:
  `codepointWidth` and `graphemes` (clusters and their widths, as with mode 2027).
- Found while testing: ghostty's Kitty encoder finds a text key by its unshifted character, so a
  `KeyEvent` without one sends its press as text and no release at all. Documented on
  `KeyEvent.unshifted` and in DESIGN.md §11.2, for M2.8's roundtrip generator.
- `ghostty-effectful-bench` (M1.10, DESIGN.md §12.3): `feed` throughput over about 1 MiB each of
  plain ASCII, SGR-coloured words, wide and combining text, and a REPL transcript of OSC 133 blocks,
  plus plain text in 4 KiB writes and a terminal opened and closed with nothing fed. CI step 8
  (§2.8) gates its allocation against `ghostty-effectful/bench/baseline/ghc-9.12.4.csv` with
  `scripts/check-allocation.py` (cassini's, 10% and a 4 KiB slack); time is reported. First
  figures: plain text at about 700 MB/s; the OSC 133 transcript at about 3.2 µs and 2.9 KB per
  stop, linear in the stops.
- libghostty-vt is pinned at its first stable release, **1.0.0** (M1.11), from commit `c7f68a7f`,
  118 commits behind it. 1.0 freezes the C ABI for 1.x (additions only, a SONAME of
  `libghostty-vt.so.1`, versioned symbols), so this should be the last migration of its size; it
  broke the C API in many small ways to get there. The pin is now a version,
  `ghostty-vt-ffi/LIBGHOSTTY_VT_VERSION` (DESIGN.md D14), built offline from the release tarball and
  its deps tarball, whose sha256 sums the build script pins (checked against upstream's minisign
  key). `scripts/prefetch-zig-deps.py`, the git checkout and the `-Dlib-version-string` stamp are
  gone. `build-libghostty.sh --release` builds for the baseline CPU, for statically linked releases
  (D17). `pkgconfig-depends` is `==1.0.0` (D15).
- The version check (DESIGN.md §3.4) compares the linked `ghostty_version()`, the headers'
  `GHOSTTY_VT_VERSION` and every optional `FEATURE_*` with the pin. `buildMetadata` reports the
  linked version (`1.0.0`), followed by any feature it lacks. `VersionMismatch` keeps its shape,
  with versions.
- The binding follows 1.0: every key enum's `INVALID = 0`; setters returning `GhosttyResult`; the
  encoders' `setopt` renamed `set`; one `uint8_t` buffer shape; `GhosttyGridRef`,
  `GhosttySelection`, `GhosttyStyle` and every callback payload frozen (no `size`; `GhosttyStyle` is
  16 bytes, its attributes and underline in a `GhosttyStyleFlags` word); the formatter's keyed
  options (`ghostty_formatter_set`/`_get`, `GhosttyFormatterOption`, `GhosttyFormatterExtras`) in
  place of its options structs; the selection-format functions removed (a selection is formatted
  through the formatter); `GhosttyCursorStyle` and `GhosttyImageLayer` merged into `types.h`;
  `ghostty_version` and `GhosttyCodepointBuffer` bound. Six shims went and two came (13 bound).
  Every bound function's rewritten doc was re-read for `safe`/`unsafe`: no mode changed.
- Public renames following upstream (D16): `ModeKey`'s constructors take the `GHOSTTY_MODE_*` names
  (`ModeKam` is `ModeDisableKeyboard`, `ModeDecckm` `ModeCursorKeys`, `ModeSyncOutput`
  `ModeSynchronizedOutput`, `ModePasteEvents` `ModeKittyPasteEvents`, and 18 more), and the
  terminal data key `CursorStyle` is `CursorSgrStyle`. `GhosttyError`'s `ShortStruct` is gone, since
  no callback receives a sized struct (regression 4's case went with it), and `ResultCode` has
  `ResultUnsupported`. `SetGlyphProtocol` is documented as off in a new terminal, as 1.0 has it.
- Fixed, the silent changes no shape check catches, each with a numbered regression case that
  failed before its fix: an OSC window title is a `GhosttyString`, not a C string, so reading it as
  one stopped at an embedded NUL and could run past the title (regression 8); a cell with no colour
  of its own is `NO_VALUE`, not `INVALID_VALUE`, so every default-coloured cell threw `Invariant`
  (regression 9); a new formatter starts with trimming and the palette, cursor-style and hyperlink
  extras on, so every option is now set on every formatter (regression 10); a null scrollback byte
  limit restores its 10,000-byte default, so no limit is now `SIZE_MAX` (regression 11).
- Fixed: the version check asked build info for the nine `FEATURE_*` keys but not
  `KITTY_GRAPHICS`, which `-Dvt-features` also gates. A 1.0.0 built without it passed the check,
  and every kitty-image key then threw `Invariant` on its `UNSUPPORTED` (regression 12).
- The format goldens are unchanged. The feed benchmark's allocation is within the gate, each
  iteration about 2 KB more, from the version check's feature queries in every `runGhostty`.
- Refactored for idiom, with no change of behaviour beyond the fixes below. `feed` folds every OSC
  stop's events onto one strict accumulator and joins `WritePty` runs once. That is about 10% less
  allocation on the feed benchmark's prompts, and 30% less on its 4 KiB writes. Operations are
  built on `ownedIO`, `countOf` and `scoped`. Result switches, out-parameter reads, buffer retries,
  string marshalling, bit flags and palettes each have one helper, in
  `Ghostty.Effectful.Internal.Error` or `.Convert`. `OscTerminator` is defined once, in
  `Ghostty.Effectful.Event`. Breaking, in the public API:
  - `encodePaste` takes `Bracketing` (`Bracketed` or `Unbracketed`) rather than a `Bool`.
  - `modeNumber` takes `ModeFamily` (`AnsiMode` or `DecPrivateMode`) rather than a `Bool`.
  - The public enums derive `Ord`, and `GhosttyError`'s `Exception` instance is written out.
- Fixed: seven calls with a documented refusal switched on their result by hand. Five of them (a
  tracked reference's point, a grid reference for formatting, an OSC datum, a cell's colour,
  grapheme or hyperlink URI, and `feed`'s `vt_write_until`) threw `Invariant` for running out of
  memory where every other call throws `OutOfMemory`. Each now goes through the shared helper, which regression 13 checks. The
  render-hold callback's function pointer is also registered masked, like the others, so an
  asynchronous exception can no longer leak it: every pointer goes through
  `Internal.Callbacks.registerFunPtr`, which regression 15 checks makes it masked and records it. A
  key or mouse encoder whose options cannot be set is freed rather than leaked: both open through
  `Internal.Error.configured`, which regression 16 checks frees a handle whose configuration throws.
  Neither failure can be produced through the public API, so each case checks the helper.
- Fixed: every region parameter was phantom, so `coerce` took a handle out of its region
  without its constructor, and `withTerminal cfg (pure . coerce)` returned a terminal the region
  then freed (#15; on master before this branch). `Terminal`, `TrackedRef`, `RenderState`,
  `Frame`, `Row`, `KeyEncoder` and `MouseEncoder` declare their region roles nominal, as `ST`
  does, and `forgetRegion` rebuilds the record rather than coercing it. Regression 14 checks, with
  deferred type errors, that each coercion no longer type-checks.
- `ghostty-effectful-bench` has a `Render` group (DESIGN.md §12.3): full frames of every cell on
  three screens, cursor and colours, and 24 frames of one new line each, gated like the feed.
  Measuring it found the refactor's per-cell readers 20% slower than before. The cause was local
  `Storable` helpers that GHC allocated as closures on every call, an `fmap` over the colour
  reads, and an unfold into a vector. All three are fixed: the render path is at parity in time
  and 2–4% under in allocation. The same fix in `getData` takes the feed's prompts to 161 MB.

### M0: infrastructure

- Seven packages under one `cabal.project`, each a skeleton wired to its neighbours in §1.3:
  `canopy-prelude`, `ghostty-vt-ffi`, `ghostty-effectful`, `tendril`, `tree-sitter-ffi`,
  `tree-sitter-effectful` and `canopy`.
- libghostty-vt pinned at `c7f68a7f`. `scripts/build-libghostty.sh` builds it, and fetches a pinned
  Zig 0.17.1 when none is installed. The Zig dependencies `zig build` cannot get are fetched
  with curl (`scripts/prefetch-zig-deps.py`), because Zig 0.17.1's fetcher fails on some machines;
