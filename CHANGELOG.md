# Changelog

Written as changes land, not at release (DESIGN.md §2.9).

## Unreleased

### M1: ghostty

- `ghostty-vt-ffi-test` is the full layout test (DESIGN.md §3.4): it parses the linked library's
  `ghostty_type_json()` and checks every bound struct's size, alignment, field names, offsets and
  sizes, and every named enum value, against the binding's `hsc2hs` values. The binding exports those
  values as descriptors (`Ghostty.FFI.Layout`), and binds `ghostty_type_json`. Each struct's `Storable`
  instance is checked against its descriptor (size, alignment, and a poke/peek round trip over
  zeroed and all-ones memory). Each enum's `Unknown` view is built from its descriptor and checked,
  through a total match, to exclude exactly the named values. `scripts/check-layout-rows.py`, in CI,
  fails if a bound type has no descriptor or no row.
- `GhosttyBuildInfo` has the `COMPLETE` set and `GhosttyBuildInfoUnknown` view §3.3 requires, which
  M0 left out.
- `ghostty-vt-ffi` binds `terminal.h` (M1.2): `Ghostty.FFI.Terminal` (lifecycle, every
  `GhosttyTerminalOption` and `GhosttyTerminalData` key with its type documented, VT writes,
  `vt_write_until` and its boundary enums, continuations, the viewport, compression, grid refs) and
  `Ghostty.FFI.Terminal.Callbacks` (every callback type with a `wrapper`, and the structs they
  receive). Also `Ghostty.FFI.GridRef` (untracked and tracked refs), `Point`, `Style`, `Device`,
  `Modes`, `Allocator`, and the parts of `color.h`, `osc.h`, `size_report.h`, `io.h` and `screen.h`
  these need. 59 descriptors, each with a layout-test row, and a behavioural test of the shims,
  callbacks and `vt_write_until`.
- DESIGN.md §3.3, §4.5 and §14.2: five functions take a struct by value, so they call
  `static inline` pointer shims (`include/gvtffi_shims.h`). The `ENQUIRY` and `XTVERSION` callbacks
  return one, so no Haskell function can be them. `terminal_reset`, `_resize`, `_set` and
  `_continuation_write` are `safe` as well as the writes, because each can run a callback, and
  `_compress` is `safe` because a full pass can stall. Tagged unions are sums, and the binding never
  supplies an allocator.
- `ghostty-vt-ffi`'s mechanical code is generated from the pinned headers by
  `scripts/gen-ghostty-ffi.py`, from templates in `ghostty-vt-ffi/gen/`, and CI checks it is current
  (`--check`). Callback types are derived from their C typedefs, and their docs are the header's.
- `scripts/check-ghostty-coverage.py`, in CI, fails on any function or type in the pinned headers
  that is neither bound nor listed in `ghostty-vt-ffi/coverage.txt` with the PLAN.md step that binds
  it, and on an entry that no longer defers anything. 132 symbols are bound and 295 deferred.
- The layout test requires every enum to name every value the library has, so a value a pin bump
  adds fails the test. `build_info.h` is now bound whole for it (`GhosttyBuildInfo`'s other eight
  keys, and `GhosttyOptimizeMode`), and DESIGN.md §2.8, §3.1, §3.3 and §3.4 say so.
- `ghostty-vt-ffi` binds render state and formatting (M1.3's first half, of the two the plan allows):
  `render.h` whole as `Ghostty.FFI.Render` (render state, update phases, every data key and
  option, row, cell and image-placement iterators, dirty iteration, row ids, the sized cursor and
  colour structs); `screen.h` whole as `Ghostty.FFI.Screen` (cell and row keys, the bulk cell view),
  now generated rather than hand-written; `selection.h` whole as `Ghostty.FFI.Selection`
  (selections, word/line/output/all derivation, adjust, order, contains, equal, one-shot formatting,
  and the gesture state machine); `formatter.h` whole as `Ghostty.FFI.Formatter`; and `types.h`'s
  `GhosttyFormatterFormat`, `GhosttyBuffer`, `GhosttyCodepoints` and `GhosttySurfacePosition`.
  105 descriptors, each with a layout-test row, and behavioural tests of each new shim, the dirty
  iteration, and the agreement of every reading path (keyed, raw, bulk, sized struct) and every
  output path (writer, buffer, allocation). 241 symbols bound, 186 deferred.
- DESIGN.md §3.3 and §14.2: at the pin, 18 functions take a struct by value and one returns one, so
  `include/gvtffi_shims.h` is now generated by `scripts/gen-ghostty-ffi.py` (`{{shim F}}`), M1.2's
  five shims with it; eleven are bound. `io.h`'s `GhosttyMimeReaderFn` receives structs by value,
  so like `ENQUIRY` and `XTVERSION` it can only be written in C. The formatter's and selection's
  format calls are `safe` although they run no callback, because they walk the scrollback.
- DESIGN.md §3.3, §5A.2 and §14.2: `capi` checks less than §3.3 said. A probe (GHC 9.12.4, GCC 16)
  showed that an integer of the wrong width or signedness converts silently and truncates, and that a
  `Ptr` to a Haskell type, so every struct pointer and every handle, reaches C as `void *` and is
  accepted for any pointer. `scripts/check-ghostty-signatures.py`, in CI, now compares each of the 94
  `capi` imports, the 22 callback types and the 48 struct records with the headers' C types by name.
  Mutating a width, a handle, a result, a pointee, a field, an array, a union arm, a synonym or a
  callback parameter each fails it. `tree-sitter-ffi` gets the same check at M4.1.
- `scripts/check-ghostty-safety.py`, in CI, ties each `safe`/`unsafe` decision to a fingerprint of
  the function's header doc and prototype (`ghostty-vt-ffi/safety.txt`), so a pin bump that changes
  what a bound function documents fails until it is re-read and recorded with `--update`. The 94
  decisions were recorded as they stand; no header doc of an `unsafe` call mentions a callback.


### M0: infrastructure

- Seven packages under one `cabal.project`, each a skeleton wired to its neighbours in §1.3:
  `canopy-prelude`, `ghostty-vt-ffi`, `ghostty-effectful`, `tendril`, `tree-sitter-ffi`,
  `tree-sitter-effectful` and `canopy`.
- libghostty-vt pinned at `c7f68a7f`. `scripts/build-libghostty.sh` builds it, and fetches a pinned
  Zig 0.17.1 when none is installed. The Zig dependencies `zig build` cannot get are fetched
  with curl (`scripts/prefetch-zig-deps.py`), because Zig 0.17.1's fetcher fails on some machines;
  only those `-Demit-lib-vt` needs, not ghostty's lazy app dependencies. The library is found through
  pkg-config at configure time.
  `ghostty-vt-ffi-test` checks that the linked build is the pinned one.
- The tree-sitter runtime is vendored at v0.27.1 (`scripts/vendor-tree-sitter.sh`).
  `scripts/gen-ts-shims.py` generates its 56 by-value shims, and CI checks them with `--check`.
- The prelude, the common stanzas and their check, hlint layering (§2.6 rules 1–7) with fixtures,
  ormolu, the Haddock floor, and CI (§2.8 steps 1–7).
- DESIGN.md §5A.2 and §14.2: the by-value function count is 56, not 46.
- DESIGN.md §3.1, §3.4 and §14.2: libghostty-vt's build info reports the library's `0.1.0-dev`
  with empty build metadata, not the app version. The build script now stamps the pinned commit in
  (`-Dlib-version-string=0.1.0-dev+<commit>`), and the identity test requires an exact match.
- Fixed, from review of the M0 PR:
  - An interrupted Zig download no longer leaves a `zig` without its `lib/` that the next run trusts:
    it unpacks beside its directory and is moved into place whole.
  - Interrupted prefetches no longer leave scratch directories inside Zig's package store.
  - `gen-ts-shims.py` finds the by-value structs in `api.h` instead of keeping a hand list, so a
    tree-sitter bump cannot add one that silently gets no shim.
  - `tree-sitter-ffi`'s sdist ships the vendored ICU and wasm libc licence files, and installs
    `tree_sitter/api.h` beside `tsffi_shims.h`, which includes it. Its C flags no longer fix `-O2`.
  - `ghostty-vt-ffi-test` compiles `GHOSTTY_COMMIT` in, so it passes when run from any directory.
  - §2.6 rule 4 no longer trusts `Main` (fixtures `ChildFromMain`, `ConcurrentFromMain`).
  - `GhosttyString`s are copied out by one function, `ghosttyStringBytes` (§3.3), in place of two
    copies; a null pointer is the empty string.
